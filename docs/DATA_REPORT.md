## 二、源格式实测结论

### 源 A：crazyxiaoqiang/Classical-Modern（主源：原文 + 白话配对）

- 目录是 **三层**，不是卷级平铺：`双语数据/战国策/<卷>/<章>/bitext.txt`。实测 33 个卷目录、495 个章目录，每章目录下恰 1 个 `bitext.txt`。
- 编码 UTF-8（无 BOM），行尾 LF。
- 记录分隔符是**空行**；单条记录固定两行，键为全角冒号的 `古文：` 与 `现代文：`。
- 全库 **6651 条记录，全部 6651 条古文/白话成对**：不成对 0、多键块 0、无法解析的行 0（实测统计，非估计）。
- 用字：**古文与白话都是简体**。原文需转繁体，这是本次最大的质量风险点，处置见第四节。

- 无注疏、无训释。

- EPUB 解包：`OEBPS/Text/NNN.htm`，共 **497 个**，文件名数字序即**书序**。
- 编码 UTF-8，`lang="zh-tw"`，**繁体**。
- 每个 htm 三段式：`<span class="style9">` 卷题（如 `卷三 ‧ 秦策一`）→ `<p class="style6">` 章题（全题）→ 若干 `<p>` 正文自然段。

## 四、切分与归一化口径

### 章

- 章序取**底本文件序**（唯一带书序的源）；章题取**底本全题**（源 A 目录名是截断前缀）。
- 对齐：卷内一对一最大权匹配，评分 = max(章题相似度, 正文相似度)；章题先经 `canon_simp`（t2s 不动点 + 异体字表）归一，前缀包含记 0.96，阈值 0.6。
- 结果：源 A 495 章 + 仅底本有 2 章 = **497 章**；仅源 A 有 0 章。那 2 章即 B 类存疑，性质是「源 A 把底本的两章并作一章」，故其白话缺失。

### 段

- 段 = **源 A 的一条「古文/现代文」配对**。不取底本自然段的原因：只有配对记录能保证每段自带对应白话，且粒度够细以承载批注锚点（底本侧有 331 章只有 1 个自然段，用作锚点太粗）。
- 超长阈值 260 字（不含标点）：全库**超阈值 0 段**，未做任何强行切分。

### text 如何转繁体（关键）

直接 `s2t` 会改错原文：OpenCC 逐字映射、不看语境，实测会出现 `咸陽→鹹陽`、`干戈→幹戈`、`周→週`、`于→於` 这类错误。因此：

1. **以繁体底本为正字来源**：把每条配对在同章底本内定位——两侧去标点后取 `SequenceMatcher` 匹配块，得「源 A 字符 → 源 B 字符」映射，再按配对区间截取底本原字符（要求覆盖率 ≥ 0.9、区间宽度 ≤ 原文长×1.3+8）；边界只补前置引号与句末句读，避免吞掉邻段标点。
2. 定位不到才回退 `s2t`，并**逐段登记**（E 类）。
3. **底本残留正字纠正**：底本个别处夹带简体专用字（实测 1 处：魏策三「无忌」→「無忌」）。管线内置 `RESIDUAL_FIX` 小表只纠正纯简体专用字，共纠正 1 处；`于/里/后/云/干/咸` 等一简对多繁的底本用字一律不动（改了才是错）。此类处仍在 F 类异文里保留，并在条目内注明「已按正字修正」。
4. 自动校核：定位片段与源 A 原文（去标点）相似度**均值 0.9927**，低于 0.85 的 **0 段**；段首误带句读 **0 段**。

### translation

- 取源 A `现代文`，本身即简体；对 16 条含繁体用字的译文补一次 t2s 归一。
- 无译文写 `null`（不写空串），并登记存疑。
- `annotations` / `glossary` 的空值不再是常态：M1b 已从 `kanripo/KR2e0003` 回填注疏与训释，口径与统计见第九节。

### 源与解析口径

源：`kanripo/KR2e0003` 四部叢刊本《戰國策校注》全 11 个 `.txt`（`_000` 序、`_001` 目錄与西周、`_002…_010` 各国正文），缓存在 `tools/_cache/kanripo/`，抓取见 `tools/kanripo_lib.py` 的 `ensure_cache`。

底本的排版是「大字正文 + 双行小字夹注」，数字化后注文被压平成圆括号：`¶` 为行末、`<pb:KR2e0003_SBCK_XXX-Ya>` 为叶码、`/` 为原双行折行处。因此解析分四步：

1. **叶码先切、再拼页**：叶码替换成哨兵、去掉 `¶` 后把全 11 档拼成一条流。
2. **跨页拼接 = 粘连只隔空白/叶码的相邻括号块**：叶末与行末都会把一条注切成两个括号块（如 `(…東周若)¶` + `(以王都為尊則舊/卷首東周是矣)` 本是「…東周若以王都為尊…」一条），只按行解析就会把注拆碎、把 `補曰` 拆成两半。实测粘合 **3285** 处，其中跨叶码 **289** 处。
3. **不用括号配平做校验器**：实测 1064 个叶里，括号在**每一个叶内各自配平**（不平衡 0 叶），所以「全书配平」证明不了任何事；真正要防的是上面那种「块被切开」。未闭合块 0 处。
4. **归属切分**：无标记的前段 =`鲍彪`；`補曰`/`𥙷曰` 起 =`吴师道补`；`正曰` 起 =`吴师道正`；`彪謂`/`彪曰` 起 =`鲍彪`。一条逻辑注可切出多段，故「注块数」与「注疏条数」不等。

### 对齐口径（不按卷/条序号）

- 鮑彪「改定其次第」并改定章题（实测其目錄作「魏鞅亡魏入秦」，通行本作「衞鞅亡魏入秦」），故**绝不按卷序/条序对齐**。
- **章**：用「章首句片段」在 kanripo 正文（去注、去句读）里投票——取章内若干 6 字 n-gram（隔 4 字取一个），每个命中位置减去它在章内的偏移后投票，得票最多且达到阈值的位置判为章首。短 n-gram 是为了扛异体/异文（`諼/驩`、`衞/衛` 这类），否则长前缀一处异文就整章对不上。
- **章内**：把本库整章正文与 kanripo 该位置起、2 倍章长 + 60 字的窗口做字符级对齐（`SequenceMatcher`），得「kanripo 字序 → 本库字序」映射，并把章的有效区间裁到真正对齐上的首尾块。覆盖率 < 0.45 判「对不上」，该章一个注都不挂。
- **段**：注块按「注文所附原文片段」的落点（注紧跟被注词之后）经映射落到章内字序，再按段偏移归属到段；落点正好在段界时归前一段。
- **锚点复核**：注前 6 字的正文片段必须与本库同位置文字相似度 ≥ 0.60，否则说明该处发生错位（本库漏句/异文吞句），该注块不挂——实测拦下 144 个。

## M3a · 史事层实体数据（人物 / 地名）

### 方法（不使用模型生成，不做模糊匹配）

1. **策展种子表**（`tools/entities_seed.py`，手写）：176 人物 + 98 地名，含繁体正字、简体、别名/异体/尊称、标签、一句话简介。`name` 一律取底本字形（底本作「衞鞅／范雎／淳于髠／閔王」就照写，不改通行字）。
2. **形态展开**（`tools/entities_lib.py: expanded_forms`）：`name` → `to_simp(name)` → 每个 alias 及其简体孪生，依序去重。繁简转换用自建逐字表（107 对），不引第三方库。
3. **精确挂载**（`tools/build_entities.py`）：对每个形态在全 6663 段 `text` 上做 `str.find` 逐次子串扫描，命中即 `{p,o,len,form}`；同一 (段,偏移) 只保留最长形态（`函谷關` 优先于别名 `函谷`）；排序键 (段落序, o, len, form)，段落序取 `book.json.volumeOrder` → 章 → 段，与阅读顺序一致，故输出与运行次数无关。

### 10.3 两条机制的口径

**(a) 全卷兜底对齐** `_fallback_align(up, cp)`：`difflib.SequenceMatcher(None, cp, up)` 取 size ≥ 6 的匹配块，按正文字距 < 300 聚簇，取总量最大的簇，再以该簇起点 −60 为锚调用既有 `_align()`，门槛仍是 `MIN_COVERAGE=0.45` / `MIN_MATCHED=50`；只有通过门槛才采用（此时 `method="volume-fallback"`）。实测 0 章通过。

**(b) 邻章复核挂载**：第一轮完全保持原行为（`_owner` = 最小跨度的归属章）；第二轮只处理第一轮没挂上的位置 p，且要求 p 仍在其归属章正文区间内（`own_s < p <= own_e`，与第一轮同口径排除章首那一位的篇題注），然后按 `(−coverage, span, id)` 依次试其它同时覆盖 p 的章，用**同一套**锚文检查（`ANCHOR_TOL=3`、注前 6 字相似度 ≥ `ANCHOR_RATIO=0.60`）复核，第一个通过者挂载。

缘由（实测）：`_owner` 取「最小包含跨度」，当邻章对齐很差时（`qi-3-07` 覆盖率仅 0.52）会把本属 `qi-3-06`（0.83）的 24 个注块位置全部吸走，随后又因自身映射错位被锚文检查否掉——注块无处可去。第二轮把这类注块交还给真正对得上的那一章。三条硬约束：不按序号猜挂、章首那位仍排除、第一轮成功的挂载绝不移动。

**试过并否决的三条**（记录在此以防重走）：

- 「按位移修正锚文」只多 1 条 → 否决，不值得为 1 条引入位移假设。
