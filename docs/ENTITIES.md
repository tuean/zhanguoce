# 实体数据层规范 v1（M3 史事层）

与 docs/SCHEMA.md 同级，是 M3 的唯一读取契约。原文/白话/注疏契约不动。

## 设计原则（先读，这决定了你能怎么填）

1. **不用 AI 批量抽实体。** 噪声与幻觉会静默污染数据，且事后无法验证。
   采用「策展种子表 + 精确字符串挂载」：实体的每一次出现都必须是**可用偏移量回原文逐字切片复核**的。
2. **实体不靠猜测对齐。** 匹配不到就是匹配不到，宁可漏，不许错挂。
3. **段 id 是唯一锚点**（沿用 SCHEMA.md）。实体挂载只写段 id + 偏移，不复制正文。

## 目录

    data/zhanguoce/entities/people.json
    data/zhanguoce/entities/places.json

## 文件结构

```json
{
  "schemaVersion": 1,
  "bookId": "zhanguoce",
  "kind": "person",
  "entities": [
    {
      "id": "person-su-qin",
      "kind": "person",
      "name": "蘇秦",
      "nameSimp": "苏秦",
      "aliases": ["蘇子", "苏子"],
      "tags": ["縱橫家"],
      "summary": "…一句话，须有出处，不确定则 null…",
      "occurrences": [
        { "p": "dongzhou-18-p0001", "o": 6, "len": 2, "form": "蘇秦" }
      ]
    }
  ]
}
```

字段：

- `id`：稳定、全局唯一，`person-` / `place-` 前缀 + 拼音或通行名。一经写入不得更改。
- `name`：繁体正字，以**底本用字**为准（例：底本作「衞鞅」不作「衛鞅」）。
- `nameSimp`：简体，供界面与简体检索。
- `aliases`：异体、简称、尊称（如「孟嘗君」/「田文」）。繁简两形都要列，否则简体检索会漏。
- `tags`：角色/身份（縱橫家、法家、國君、將領…），可为空数组。
- `summary`：一句话简介。**不确定就写 null**，禁止编造生卒年、官职、事迹。
- `occurrences`：每次出现一条。`p` 段 id；`o` 该实体在段 `text`（繁体原文）中的**字符偏移**（0 基，按 Unicode 标量计）；`len` 匹配长度；`form` 实际匹配到的字形。

## 硬性约束（校验器会逐条查）

1. **偏移必须可复核**：对每条 occurrence，`段.text[o .. o+len] == form` 必须成立。不成立即 FAIL。
2. `form` 必须等于该实体的 `name` 或某个 `aliases` 之一。
3. 段 id 必须真实存在。
4. 每个实体至少有 1 条 occurrence（不许有悬空实体）。
5. `id` 全局唯一，人物与地名之间也不得重名。
6. `name` 用繁体；`text` 是繁体，所以繁简混用会导致偏移对不上——这正是第 1 条会自动拦住的东西。
7. 无 BOM、UTF-8、LF、2 空格缩进。

## 覆盖要求（M3 的验收线）

- 人物 ≥ 120，地名 ≥ 60。
- 覆盖到战国策主线人物：蘇秦、張儀、孟嘗君、平原君、信陵君、春申君、商鞅（底本作衞鞅）、范雎、蔡澤、樂毅、田單、藺相如、廉頗、白起、趙武靈王、燕昭王、齊湣王、楚懷王、秦昭王、魏冉、甘茂、公孫衍、陳軫、蘇代、蘇厲、觸讋、馮諼、毛遂、唐雎、魯仲連 等；
  以及国别地名：秦、齊、楚、趙、魏、韓、燕、宋、衛、中山、東周、西周，及主要城邑关隘（咸陽、邯鄲、臨淄、郢、大梁、洛陽、宜陽、函谷關、長平 等）。
- 报告实际覆盖率：**含至少 1 个实体的段数 / 6663**。
