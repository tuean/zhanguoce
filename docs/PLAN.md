## 三、为什么不能照搬读通鉴的骨架

读通鉴是《资治通鉴》——**编年体**，导航轴是 帝王 → 年号 → 年 → 段。
《战国策》是**国别体**，导航轴必须是 国策(11) → 卷(33) → 章 → 段，另有「策士游说」这一层语义。
照搬时间轴会得到一棵错的树。故本方案把「结构轴」做成书籍自带元数据（form + groups），而非硬编码。

## 四、数据模型

    data/<book-id>/book.json            书目 + 分组(国别) + 卷序
    data/<book-id>/volumes/<vol>.json   卷 → 章 → 段（原文/白话/注疏/训释）

三处关键设计：
- **段（paragraph）是最小锚点**，带稳定 id。批注、AI 追问、史事关联、谋略拆解全部挂在段 id 上——一次建模，四层功能共用。
- **注疏是数组不是字符串**：annotations: [{source, text}]，各家学说可并存，也可为空（源未解决时不阻塞）。
- **训释挂在段上**：glossary: [{term, pinyin, gloss}]，供划词即查。

详见 docs/SCHEMA.md。

## 七、注疏来源结论（调研 + 我独立复核）

| 目标 | 状态 | 来源 |
|---|---|---|
| 鲍彪注 | 可直取 | kanripo/KR2e0003 raw（实测 200，text/plain utf-8） |
| 吴师道补正 | 可切分 | 同上，補曰 / 正曰 标记 |
| 高诱注 | **挂起** | 高诱注本仅存影像（士礼居 / 剡川姚氏本）。此为版本问题非搜索失败：kanripo 三本正文 高誘=0 |

三条会影响实现的硬约束：

1. **抓取器必须按叶码切段后跨页拼接**——注块会被叶码标记切断，实测存在未闭合注块，故不能用括号配平做校验。
2. **不能按卷/条序对齐原文**——鲍彪「改定其次第」，实测目录题作「魏鞅亡魏入秦」而通行本作「衛鞅亡魏入秦」。注疏须按「章题 + 首句」模糊挂载，对不上的一律进存疑清单。
3. **glossary 主路是从注文反抽**——注文本身即训释，如 (詘服/也) → 詘 = 服也。零外部依赖，优于外部词典接口。

**依赖关系**：注疏入库必须排在 T1 章切分产出之后（需按章题+首句匹配），故列为 M1b 而非与 M1 并行。

## 九、并行作业的教训（防复发）

M2a 与 M2b 共用一个 Cargo workspace。当 M2b 改了 members 而 src/main.rs 尚未落地时，cargo test --workspace 会因 target 解析失败整体变红。
**规则**：并行期间用 cargo test -p <crate> 隔离验证；全部任务收口后必须重跑一次 cargo test --workspace，不得以「当时是绿的」当作结论。

## 十、同一个数字落到三处 —— 这次翻车的真正形态

「12 组」这个错误数字，我写进了三处：发给数据侧的简报、发给内核侧的验收标准、以及数据产出本身。
改数据后，内核测试 `assert_eq!(data.group_count(), 12)` 立刻变红：`left: 11, right: 12`。

教训不是「要记得同步改」，而是：

1. **验收标准里的绝对数字，是跨任务的隐式契约**。改它等于同时改多个任务的边界。
2. 收到子代理「实测 33/12/497/6663」的回报时，**数字对上了不等于数字对**——如果我的基准本身错了，三方会一致地错。
   这次能发现，是因为 M2b 把目录树真渲染出来了，重复才暴露成 546 个链接。**渲染是唯一能拆穿数据层自洽性谎言的东西。**
3. 已在两处补防复发断言：数据侧 `任何卷不得被多个 group 引用`；内核侧同款断言（本次追加）。
